# NFCC · 下界堡垒十字路口工具

给 Minecraft 26.2 用的两个东西，一个在电脑上算，一个在游戏里干活：

| | 名字 | 干什么 | 形态 |
|---|---|---|---|
| 桌面版 | **NFCC** | 按种子搜多连堡垒、算 128 格球心、统计每个路口的组件覆盖情况 | 单文件 jar，双击即用 |
| 模组版 | **NFCC-NetherFortressCrossingCalculator** | 在游戏里把算好的结果落地：清空、补件、画框、算球心、统计 | Fabric 模组 |

两边都用同一套组件生成逻辑，算出来的路口坐标是一致的。

---

## 一、NFCC（桌面版）

### 用法

打开就一个窗口，左右两块：

- **左边：多连堡垒搜索**。填种子和搜索半径，找「几座堡垒互相靠得够近」的组合，结果是一张表，点表头能排序。点某一行的中心点，右边的分析器会自动接着算这一座。
- **右边：十字路口分析**。给定种子、中心点、半径（最大 512 格），列出这一片里的全部十字路口、球心、统计。

### 搜索

- 搜的是「相邻堡垒间距 ≤ N 格、至少 k 座」的组合，滑窗扫描，很吃 CPU，线程数可以调。
- 可以只算灵魂沙峡谷里的（刷凋灵骷髅的选择），也可以不限。
- 结果表会自动去重、可以按任何一列排序，行还能手动拖到想要的位置；保存时按当前显示顺序导出 tsv。
- 表格里除了连数、中心点、距原点、平均间距、堡垒坐标，还有「可刷怪」「占总体积」「峡谷刷怪」「峡谷刷怪占总体积」四列。
- 3 连以上的行会自己算，算完把中心点、距原点、四列数据直接填回表里（「可刷怪」永远是总可刷怪块数，「峡谷刷怪」才是灵魂沙峡谷的那份）。
- 2 连的留空，点哪行算哪行；想一次算完就按「计算全部十字路口」。
- 满 100% 的行标淡绿底：口径是「没有重叠」且覆盖块数 ≥ 3610 × 路口数。
- 排序：点表头任意一列排序（距原点、平均间距先小到大，其它先大到小），再点一次反向。

### 分析

- 算 128 格球形挂机点，候选按 x/z 步 8、y 步 4 粗搜，再 ±4/±2/±1 细搜。
- **多联优先**：先看这颗球能覆盖到几座堡垒，再看能覆盖多少路口，最后才比离重心远近。
- 并列时 y 偏差扣得重。
- 口径和游戏里那套完全一致：能刷怪 = 距离 ≤ 128 且挂机空腔（3×3×3）离路口够远（> 24 格）；球心上方的 3×3×3 必须是空的。

### 输出里那些颜色是什么意思

| 颜色 | 意思 |
|---|---|
| 绿 | 整座十字路口都在 128 格球里 |
| 黄 | 只有一部分在球里 |
| 红 | 整座都在球外 |
| 橙 | 几座路口互相重叠的那块 |
| 棕 | 不在灵魂沙峡谷里的十字路口 |
| 群系色 | 路口所在群系（下界荒地 / 绯红森林 / 诡异森林 / 玄武岩三角洲） |
| 棕 | 灵魂沙峡谷里的十字路口 |
| 其它 | 不在灵魂沙峡谷的路口，后面跟群系名，颜色跟群系走 |

### 运行环境

- Windows x64
- Java 25（`javaw -jar NFCC.jar`，双击也行）

## 二、NFCC-NetherFortressCrossingCalculator（模组版）

### 装法

1. Minecraft 26.2 + Fabric Loader 0.20.1+
2. Fabric API 0.161.0+26.2
3. 把 `NFCC-NetherFortressCrossingCalculator-0.1.0.jar` 丢进 `mods/`

### 命令

全部在 `/nfcc` 下面，需要权限等级 2（gamemaster）。

先 `/nfcc clear` 圈定区域，再选下面两种算法之一，跳步会被拒绝。

```
/nfcc seed [值]                                 看/设种子（不设就用存档种子）
/nfcc clear <半径> [complete]                   以自己为中心清空，默认 normal（清到 Y143）
/nfcc clear <pos1> <pos2> [complete]            清空指定矩形
/nfcc calc cross <soul|normal>                  十字路口模式：算球心 + 统计，然后贴回路口、画框，一条命令跑完
/nfcc calc normal <soul|normal>                 整座堡垒体积模式：只算总体积 / 灵魂沙体积 / 百分比，再按子分支定中心点
/nfcc stop                                      停掉当前正在跑的整个任务
```

- `clear` 不带参数就是 `normal`（清到 y=143），加 `complete` 才清到 y=255；清的时候连十字路口一起清，清完会顺带报一遍堡垒总体积。
- `calc cross` 一条命令做三件事：算中心点与统计 → 把十字路口缺的下界砖贴回去 → 按统计结果画框。顺序上不分先后，跑完就是三件都做完。
- `calc cross soul` 只把灵魂沙峡谷里的路口算进「值得刷」的统计；`normal` 则算全部群系。
- `calc normal` 的「体积」是整座堡垒全部组件包围盒之和，不是路口体积；`soul` / `normal` 只影响算中心点时用哪批路口。
- 画框用染色玻璃：绿=全在球内、黄=部分、红=全在球外、橙=重叠；路口框外扩 1 格，重叠框外扩 2 格。
- 提示文字「等待加载…」每 tick 刷一次，不会自己消失，`/nfcc stop` 时一起清掉。

### 它会怎么干活

- **绝不强制加载区块**。只动已经加载的区块，没加载的排队等玩家走过去，等的时候 actionbar 会一直写「等待加载清理：x y z」（每 tick 刷一次，不会自己消失，`/nfcc stop` 时跟着清掉）。
- 进度条在 bossbar 上，紫色，速度大概是每 tick 一块区块。
- `place` 只往空气里贴方块，所以不会覆盖你原来的东西。
- `check` 只画框，颜色优先级 橙 > 红 > 黄 > 绿，也只往空气里画。框是**染色玻璃**：橙 / 红 / 黄玻璃，绿色用黄绿（lime）玻璃；路口框外扩 1 格，重叠那块外扩 2 格。

### 统计口径

- 每个方块只算一次，重叠的部分按优先级取一个颜色。
- 完全包含 = 绿，部分包含 = 黄，完全不含 = 红，重叠多出来的部分单独记。

### 每一步的输出

**clear**

```
> 正在努力清空~ 区域内有 10 个十字路口
> 清空完毕，共 10 个十字路口
```

清的过程中 bossbar 上是 `清空进度 ++++++-- 63%`，区块没加载时 actionbar 是 `等待加载清理：-368320 58 -483104`。

清空一律按严格模式处理：方块连流动的流体一起按死，不给邻居更新，所以不会出现清完又被旁边岩浆灌回来的情况。十字路口也一起清掉，后面 `place` 再贴回去。

**place**

```
> 正在补齐十字路口~
> 十字路口补齐完毕啦~ 共 10 座
```

**calc**

```
计算出来的中心挂机点： ( -29374722 68 -11999417 )
其 128 格半径球体刷怪范围内十字路口的情况
完全包含： 7  |  不完全包含： 3  |  完全不包含： 0
存在重叠的十字路口
1. ( -29374793 68 -11999442 )
2. ( -29374799 68 -11999451 )
不在灵魂沙峡谷的十字路口：
1. ( -29374779 73 -11999413 )  玄武岩三角洲
2. ( -29374799 73 -11999451 )  玄武岩三角洲
总体积： 5000 块
范围内可刷怪： 3500 块 ( 3500 + 0 + 0 )
       占总体积： 70.0 %
范围内可刷怪且位于灵魂沙峡谷： 3500 块
       占可刷怪体积： 100.0 %  占总体积： 70.0 %
不可刷怪： 1500 块 ( 0 + 1500 + 0 )
       占总体积： 30.0 %
这片共 10 个十字路口
点一下就填好 /tp，回车才走：( -29374722 68 -11999417 )
```

所有坐标都能点，点了只把 `/tp` 填进聊天框，不会自己传送。算完会在球心下面铺一块 3×3 平台（正中红色染色玻璃）。

输出顺序跟桌面版一致：中心挂机点 → 其 128 格半径球体刷怪范围内十字路口的情况 → 重叠 → 不在灵魂沙峡谷 → 完全包含 / 不完全包含 / 完全不包含 → 总体积 → 范围内可刷怪（绿的 + 黄的 + 橙的）→ 占总体积 → 范围内可刷怪且位于灵魂沙峡谷 → 占可刷怪体积 / 占总体积 → 不可刷怪 → 占总体积。总体积一律按 3610 × 路口数算。

**check**

```
> 正在画框~
> 画框完毕
```

画完去球心那儿往下看：橙框是重叠的那几块，红框是白算的路口，黄框只有一部分在球里，绿框全都划算。

## 构建

桌面版（纯 JDK，不需要 Gradle）：

```
javac -encoding UTF-8 -d classes *.java
gcc -O2 -I<cubiomes 头文件> engine.c <cubiomes 源码> -o engine.exe -lm
jar --create --file NFCC.jar --main-class MergedApp -C classes . -C engine .
```

模组版（Gradle 9.8.2 + JDK 25）：

```
gradle build
# 产物：build/libs/NFCC-NetherFortressCrossingCalculator-0.1.0.jar
```
